# LMS TSUE — автозаход на пары

Скрипт сам входит в `lms.tsue.uz` через HEMIS, читает расписание на сегодня из API LMS
и в нужное время заходит на пару (BigBlueButton), оставаясь там до конца занятия.

## Установка

```bash
pip3 install -r requirements.txt
python3 -m playwright install chromium
```

## Настройка

`.env`:

```
HEMIS_LOGIN=...       # логин HEMIS (Talaba ID)
HEMIS_PASSWORD=...
HEADLESS=0            # 0 — показывать окно браузера, 1 — без окна
```

## Команды

```bash
python3 lms_auto.py --list            # расписание на сегодня (проверка API)
python3 lms_auto.py --now             # зайти в пару, которая идёт сейчас
python3 lms_auto.py --now --stay 5    # то же, но выйти через 5 минут (тест)
python3 lms_auto.py                   # планировщик: ждёт пары и заходит сам
python3 lms_auto.py --from-time 14:30 # не входить в пары, начавшиеся раньше 14:30
python3 lms_auto.py --wake-plan       # команды для пробуждения Mac перед парами
python3 lms_auto.py --wake            # поставить пробуждения (спросит пароль sudo)
```

Планировщик проверяет расписание каждые 30 секунд, заходит за минуту до начала пары,
держит сессию всё занятие (обычно 80 минут — до времени окончания из LMS) и выходит.
Если связь оборвалась или выкинуло — сам переподключается. Токен обновляется автоматически.

## Звук

После входа в комнату BBB всплывает вопрос «Как вы хотите присоединиться к аудио?» —
скрипт всегда нажимает **«Только слушать»** (`Listen only` / `Faqat tinglash`), микрофон
не включает. Если диалога нет (браузер сам пустил слушателем) — просто продолжает.

## Сон и пробуждение

- Пока работает планировщик, он запускает `caffeinate`, поэтому Mac не засыпает
  и пара не пропускается (`caffeinate` автоматически завершится вместе со скриптом).
- Если Mac всё-таки уходит в сон (например, закрыта крышка), системе нужно разрешение
  разбудить себя. Разово выполните в Терминале:

```bash
python3 lms_auto.py --wake          # спросит пароль и поставит pmset-пробуждения
# или вручную:
sudo pmset schedule wake "11/12/26 09:25:00"
```

  Проверить, что будильники стоят: `pmset -g sched`.
  После смены расписания команду `--wake` нужно повторить.

## Docker

```bash
docker compose build          # собрать образ lms-auto:latest
docker compose up -d          # запустить (рестарт при падении и перезагрузке)
docker compose logs -f        # логи
docker compose down           # остановить
```

Образ: `python:3.12-slim` + Chromium из Playwright, работает от непривилегированного
пользователя, `CHROMIUM_ARGS=--no-sandbox` уже прописан в compose.
`.env` в образ не попадает — передаётся через `env_file`, скриншоты монтируются в `./screenshots`.
Таймзона `Asia/Tashkent` задана и в образе, и в compose.

Образ собирается из `python:3.12-slim`, Chromium (playwright 1.60) лежит в `/ms-playwright`,
контейнер работает не от root. Итог: `lms-auto:latest` (~2.2 ГБ на диске).

Проверка без запуска планировщика:

```bash
docker compose run --rm --no-deps lms-auto python lms_auto.py --list
```

## Сервер: запустил один раз — работает всегда

```bash
git clone/copy проект, заполни .env
bash deploy/install.sh          # venv + chromium + systemd-сервис + автозапуск
tail -f lms.log                 # что происходит
systemctl restart lms-auto      # перезапустить
systemctl stop lms-auto         # остановить
```

Сервис `lms-auto`:

- стартует при загрузке сервера (`enable`), падение — перезапуск через 30 сек (`Restart=always`);
- внутри скрипта свой супервизор: любое исключение ловится, браузер перезапускается;
- токен обновляется сам, при обрыве связи в паре — переподключение (до 20 попыток);
- `TZ=Asia/Tashkent` уже прописан, время пар берётся из LMS.

На сервере нужен Python 3.9+ и права на установку chromium-зависимостей
(`python3 -m playwright install --with-deps chromium`, если systemd-служба не стартует —
поставь зависимости этой командой вручную).

## Запуск в фоне

```bash
nohup python3 lms_auto.py >> lms.log 2>&1 &
tail -f lms.log          # смотреть, что происходит
pkill -f lms_auto.py     # остановить
```

Важно: ноутбук должен быть включён и не спать (иначе процесс встанет вместе с системой).

## Как это устроено

1. `lms.tsue.uz/login` → кнопка «HEMIS orqali kirish» → форма HEMIS → JWT в `localStorage`.
2. `GET /api/dars/talaba/darslarim/?dan=…&gacha=…` — пары на день: время, статус,
   `kirish_ochiqmi` (открыт ли вход).
3. `GET /api/dars/talaba/darsxona/{id}/kirish/?redirect=false` — та же ссылка, что отдаёт
   кнопка «Darsga kirish»; открываем её в браузере и оказываемся в комнате BBB.
4. В комнате нажимаем «Только слушать» и держим вкладку до конца пары.

Ничего не хардкодится: расписание всегда берётся из LMS, поэтому старый `schedule.json`
больше не нужен (лежит рядом как `schedule.json.bak`).

## Важно

- `env.example` содержит реальные логин и пароль — уберите их оттуда, если файл куда-то
  отправляется. `.env` уже добавлен в `.gitignore`.
- Скрипт работает только с вашим аккаунтом; заход в пару отмечается как присутствие,
  как если бы вы открыли её вручную.
